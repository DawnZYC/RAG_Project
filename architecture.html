检索层（两个可切换的后端）

🔍
检索后端（工厂模式，RAG_BACKEND 切换）
retrieval/factory.py → vector_store.py 或 llamaindex_store.py · API 接口和生成层无需改动
① native 后端（默认，RAG_BACKEND=native）
嵌入模型SentenceTransformer（本地，无 API 费用）
存储ChromaDB PersistentClient 直连
相似度计算余弦距离 d → score = 1 − d/2，范围 [0,1]
检索collection.query()，纯余弦相似度排序
来源过滤where={"source": filename}
学习价值无框架封装，最直接理解 RAG 原理
② llamaindex 后端（RAG_BACKEND=llamaindex）
嵌入模型HuggingFaceEmbedding（本地，同款模型）
存储ChromaVectorStore → VectorStoreIndex
检索模式similarity（纯相似度） / mmr（多样性）
MMR 候选池fetch_k = top_k × 4，从中做多样性筛选
MMR 参数mmr_threshold：0.0=最多样，1.0=最相关
来源过滤MetadataFilters + ExactMatchFilter
⚠ 切换后端后必须清空并重新 ingest（embedding 格式不兼容）： rm -rf data/chroma/*

拒答机制（双重保险）

🚫
Pre-LLM + Post-LLM 双重拒答
generator.py · _should_refuse() + INSUFFICIENT_EVIDENCE 前缀
第一道：Pre-LLM（分数阈值）
检索完成后立即判断，不调用 LLM，响应速度极快（<50ms）。

• 知识库为空 → 拒答，提示用户先上传文档
• top_score < 0.35（SCORE_THRESHOLD）→ 拒答，返回分数和阈值

优点：节省 Token，响应快，逻辑透明可调。
阈值定义位置：vector_store.py
第二道：Post-LLM（语义判断）
LLM 生成后检查回答前缀，捕获分数过关但实质无关的情况。

• System Prompt 要求 LLM 在上下文不足时回复 INSUFFICIENT_EVIDENCE: 原因
• 检测到该前缀 → 拒答，提取原因返回给用户

优点：语义层面兜底，处理相似度数值虚高但内容不相关的边缘案例。

多轮对话 Memory + Query Rewriting

🧠
Session 与 Memory 管理
routes.py · app.state.sessions 内存字典
🆔
Session 标识
UUID 由前端生成，随每次请求传入 session_id 字段。不传 = 单次问答模式，行为与原来完全一致。
📜
历史存储格式
[{"role":"user","content":"..."}, {"role":"assistant","content":"..."}] 交替存储，与 OpenAI messages 格式完全一致。
🪟
滑动窗口（MEMORY_WINDOW_K=5）
超过 10 条消息时删最旧一轮（2条）。手动 list 切片实现，无额外依赖，Context 不会无限增长。
💉
历史注入方式
注入为真实 LangChain message 对象（SystemMessage / HumanMessage / AIMessage），不做字符串拼接。LLM 能正确理解对话结构和指代关系。
✏️
Query Rewriting（检索前改写）
generator.py · rewrite_query() · LangChain LCEL
❓
为什么要在检索前改写
追问"国际订单呢？"的向量语义极弱，直接检索命中率很低。改写为"国际订单的退款政策是什么？"后向量精准，检索结果才有意义。
⚙️
实现
LangChain LCEL chain：prompt | ChatOpenAI(temperature=0) | StrOutputParser()，异步 ainvoke()。temperature=0 保证改写确定性。
⚡
优化策略
无历史时直接返回原问题，跳过 LLM 调用（节省 Token）。改写失败时 fallback 原问题，不中断主流程。
对话 + 改写示例
Q1: "退款政策是什么？"
A1: "30天内可退，需保留小票..."
Q2（追问）: "国际订单呢？"
→ 改写后检索: "国际订单的退款政策是什么？"
A2: "国际订单退款需90天内..."
Q3（追问）: "那第二条规则？"
→ 改写后检索: "国际订单退款政策的第二条规则是什么？"

API 接口

🔌
REST API（统一前缀 /api/v1）
app/api/routes.py · 交互文档：http://localhost:8000/docs
POST /ingest 上传文档并 ingest（multipart/form-data）→ {filename, chunks_added, status}
POST /query 同步问答，支持 session_id → {answer, refused, refuse_reason, sources, latency_ms, session_id}
POST /stream 流式问答（SSE），支持 session_id → token 事件流 + done 事件（含 sources）
GET /health 健康检查 → {status: "ok"}
GET /stats 向量库统计 → {total_chunks, collection, model, active_sessions}
DELETE /document/{filename} 删除某文档的所有 chunk（重新 ingest 前调用）
DELETE /session/{session_id} 清空会话历史（前端"新对话"时调用）
GET /session/{session_id} 查看会话历史（调试用）→ {turn_count, history}
